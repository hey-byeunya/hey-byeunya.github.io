## Q. HTTPS는 HTTP랑 뭐가 다른가요?

**A.** HTTP에 **암호화**를 더한 버전이에요. 브라우저 주소창의 자물쇠 아이콘이 이걸 의미해요.

> 엽서(HTTP) 대신 봉투에 넣고 잠근 편지(HTTPS)예요. 중간에서 누가 봐도 내용을 못 읽어요.
{: .prompt-tip }

자물쇠가 뜨려면 두 가지가 다 필요해요: ① 공개키/개인키로 암호화가 되는지, ② 인증기관이 "이 사이트 진짜 맞다"고 서명해줬는지. 암호화만 되고 서명이 없으면(자체 서명 인증서) 브라우저는 자물쇠 대신 경고를 띄워요.

## Q. 공개키/개인키는요?

**A.** 잠그는 열쇠(공개키)와 여는 열쇠(개인키)가 다른 암호화 방식이에요.

> 공개키 = 누구나 편지를 넣을 수 있는 우체통 투입구(공개해도 됨). 개인키 = 그 우체통을 여는 유일한 열쇠(서버만 보유). 📬
{: .prompt-tip }

계산이 느려서, 실제 통신에서는 접속 초반에만 이 방식으로 "오늘 하루만 쓸 임시 열쇠(세션 키)"를 주고받고, 이후엔 빠른 대칭키로 대화해요. 이 첫 인사 과정이 **TLS 핸드셰이크**예요.

## Q. TLS 핸드셰이크와 인증기관(CA)은요?

**A.**
- **TLS 핸드셰이크** — 브라우저와 서버가 접속 초반에 나누는 "첫 인사". 여기서 임시 세션 키를 정해요. 🤝
- **인증기관(CA)** — "이 사이트 진짜 맞아요"라고 보증해주는 신뢰받는 제3자. 신분증의 정부 발급 도장 🛂

암호화(공개키/개인키)와 신뢰(CA 서명)는 별개예요. 자체 서명 인증서를 쓰면 암호화는 되지만 CA 서명이 없어서 브라우저가 신원을 확인 못 해요.

> 자물쇠 = 암호화 + CA의 신원 보증, 둘 다 있어야 떠요.
{: .prompt-warning }

## Q. REST API와 GraphQL은 뭐가 다른가요?

**A.**
- **REST API** — 자원마다 주소(URL)를 정해두고 HTTP 메서드(GET/POST 등)로 다루는 방식. 세트 메뉴처럼 정해진 구성이 통째로 나와요. 🍱
- **GraphQL** — 필요한 데이터 필드만 콕 집어 요청하는 쿼리 언어. 뷔페에서 원하는 것만 담는 것처럼요. 🍽️

```
REST:     GET /users/1/posts   (정해진 세트로 응답)
GraphQL:  query { user(id:1) { name, posts { title } } }  (원하는 필드만)
```

| 구분 | REST | GraphQL |
|------|------|---------|
| 엔드포인트 | 자원마다 여러 개 | 보통 하나 |
| 데이터 양 | 정해진 세트 | 요청한 만큼만 |
| 오버/언더페칭 | 자주 발생 | 없음 |

> GraphQL이 REST의 오버/언더페칭 문제를 해결하지만, 학습 난이도와 캐싱은 REST가 더 유리해요. 데이터는 둘 다 JSON으로 주고받아요.
{: .prompt-tip }
