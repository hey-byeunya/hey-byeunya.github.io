AI 코딩 도구를 쓰다 보면 프로젝트 폴더에 `.md` 파일이 자꾸 생겨요. `CLAUDE.md`, `AGENTS.md`, 그리고 `SKILL.md`. 셋 다 "AI에게 규칙을 알려주는 파일"이라 이름만 보면 구분이 안 되는데, 오늘 이 셋의 차이를 정리했어요.

## Q. 셋을 가르는 진짜 기준이 뭐예요?

**A.** **"언제 읽히는가"**예요. 담는 내용이 아니라 **로드 시점**이 셋을 가릅니다.

| | CLAUDE.md | AGENTS.md | SKILL.md |
|---|---|---|---|
| 로드 시점 | **항상** | **항상** | **필요할 때만** |
| 평소 점유 | 전문 | 전문 | 요약 한 줄 |
| 읽는 도구 | Claude Code | 여러 도구 | Claude |
| 담는 것 | 상태·규칙 | 상태·규칙 | 작업 **절차** |

`CLAUDE.md`와 `AGENTS.md`는 담는 내용이 거의 같아요. 차이는 **누가 읽는지**뿐이에요. `SKILL.md`만 성격이 다릅니다.

> 여행 갈 때 **여권은 항상 주머니에**(CLAUDE.md) 넣고, **등산 장비는 등산할 때만**(SKILL.md) 꺼내는 것과 같아요. 주머니에 등산 장비까지 넣고 다니면 무겁죠. 🎒
{: .prompt-tip }

## Q. CLAUDE.md는 뭐예요?

**A.** Claude Code가 **대화를 시작할 때마다 자동으로 읽는** 프로젝트 설명서예요. "이 프로젝트는 Next.js를 쓴다", "비밀 키는 절대 커밋하지 않는다" 같은, **모든 작업에 걸리는 규칙**을 적어둡니다.

계층이 있어서 여러 군데 둘 수 있어요.

- `~/.claude/CLAUDE.md` — 내 모든 프로젝트에 적용되는 전역 규칙
- 프로젝트 루트의 `CLAUDE.md` — 그 프로젝트 규칙
- 하위 폴더의 `CLAUDE.md` — 그 폴더 파일을 만질 때만 읽힘

> **항상 읽힌다는 건 항상 비용이 든다는 뜻**이에요. AI는 한 번에 읽을 수 있는 양(컨텍스트)이 정해져 있어서, 이 파일이 커지면 그 프로젝트에서 여는 **모든 대화가** 그만큼 무거워져요.
{: .prompt-warning }

## Q. AGENTS.md는 CLAUDE.md와 뭐가 달라요?

**A.** 내용의 성격은 거의 같고, **읽는 도구가 다릅니다.** `CLAUDE.md`는 이름 그대로 Claude용인데, AI 코딩 도구는 Claude만 있는 게 아니잖아요. Cursor, Codex, Copilot, opencode… 도구마다 자기 이름의 설정 파일을 요구하면 같은 내용을 여러 번 써야 해요.

`AGENTS.md`는 그래서 만들어진 **도구 중립 규격**이에요. 여러 도구가 이 파일 하나를 같이 읽습니다.

> 여러 나라를 여행할 때 나라마다 다른 콘센트를 쓰지 않고 **멀티어댑터 하나**를 챙기는 것과 비슷해요. 🔌
{: .prompt-info }

한 프로젝트에서 도구를 여러 개 쓴다면, 공통 규칙은 `AGENTS.md`에 두고 `CLAUDE.md`에서 그걸 불러오는 방식을 쓸 수 있어요.

## Q. @ 임포트로 파일을 나누면 가벼워지나요?

**A.** **아니요. 이게 오늘 배운 함정이에요.** `CLAUDE.md`에 `@다른파일.md`라고 쓰면 그 파일 내용을 끌어와서 합쳐주는데, **끌어온 것도 항상 읽힙니다.**

> 파일을 10개로 쪼개고 전부 `@`로 불러오면, **파일 개수만 늘고 AI가 읽는 양은 그대로**예요. 서랍을 나눴을 뿐 짐은 다 들고 가는 셈이죠.
{: .prompt-danger }

진짜로 가볍게 하려면 `@`를 쓰지 말고, **"이 작업을 할 때 이 파일을 읽어라"라고 경로만 평문으로 적어두면** 돼요. 그러면 필요할 때만 읽히니까요.

## Q. SKILL.md는 뭐고, 왜 안 무거워요?

**A.** **스킬 하나를 정의하는 파일**이에요. "블로그에 글 올리는 절차", "PR 리뷰하는 절차"처럼 **특정 작업의 방법**을 담습니다.

핵심은 **점진적 공개(progressive disclosure)** 라는 방식이에요. 평소에는 파일 맨 위의 `name`과 `description` **한두 줄만** 읽혀 있고, 지금 하려는 일이 그 설명과 맞을 때 **비로소 본문 전체가 들어와요.**

```
---
name: post-til
description: 오늘 배운 용어를 블로그에 올린다. "TIL 포스팅", ...
---

(본문 — 조건이 맞을 때만 읽힘)
```

> 도서관 서가에서 **책등의 제목만 훑어보다가**, 필요한 책 한 권만 꺼내 펼치는 것과 같아요. 스킬이 20개여도 평소엔 제목 20개만 보고 있는 거죠. 📚
{: .prompt-tip }

그래서 `description`이 스킬의 절반이에요. 여기에 어떤 상황에서 쓰는지("~해줘"라고 말할 때 등)를 구체적으로 적어두지 않으면, 본문을 아무리 잘 써도 **꺼내지지 않아요.**

## Q. 그럼 뭘 어디에 써야 해요?

**A.** 세 줄로 정리하면 이래요.

1. **모든 작업**에 해당하면 → `CLAUDE.md`
2. **특정 상황**에만 해당하면 → `SKILL.md`
3. **다른 도구**도 알아야 하면 → `AGENTS.md`

여기서 제일 자주 하는 실수는 **2번을 1번에 넣는 것**이에요. 특정 화면을 고칠 때만 필요한 규칙을 `CLAUDE.md`에 넣으면, 그 화면과 무관한 모든 대화가 그 비용을 냅니다.

> 실제로 제 프로젝트의 `CLAUDE.md`를 재보니 **18KB**였고, 그중 **77%가 특정 상황에만 필요한 내용**이었어요. 항상 필요한 건(보안 규칙, 비밀 키 금지 같은) 3KB뿐이었죠.
{: .prompt-info }

## Q. 그러면 큰 CLAUDE.md는 어떻게 줄여요?

**A.** 오늘 실제로 이렇게 줄여봤어요.

1. **틀리면 되돌릴 수 없는 규칙만 남긴다** — 보안, 비밀 키 관리처럼 놓치면 사고가 나는 것.
2. 나머지는 **주제별 문서로 옮긴다** — `docs/rules/폼규칙.md` 처럼.
3. 원래 파일 끝에 **"어떤 작업엔 어떤 문서를 읽어라" 목록**을 둔다.

3번에서 중요한 건, **경로만 적지 않는 것**이에요. `docs/rules/fields.md` 라고만 쓰면 열어볼지 판단할 근거가 없어서 그냥 지나쳐요. `폼·필드 규칙 (카테고리 검증, 수량, 상태) → docs/rules/fields.md` 처럼 **괄호에 키워드 요약**을 붙여야 해요. 그래야 지금 하려는 일과 관계있는지 열어보기 전에 판단할 수 있어요.

> 결과: 18KB → 4.5KB (**74% 감소**). 규칙 문장은 하나도 안 지웠고, 있던 자리만 옮겼어요.
{: .prompt-tip }

⚠️ 단, 이 방식엔 트레이드오프가 있어요. 목록은 **자동으로 읽히지 않으니** AI가 실제로 그 문서를 열어야 효력이 생겨요. 그래서 **놓치면 복구 불가능한 규칙은 절대 밖으로 빼지 않는** 게 안전장치예요.
